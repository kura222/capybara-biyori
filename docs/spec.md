## 2. 技術スタック（承認事項②）

| 層 | 採用 | 理由 |
|---|---|---|
| サイト生成 | **Astro（静的出力・TypeScript）** | コンテンツサイト向けSSGの定番。デフォルトJSゼロで高速=SEO/CWVに直結。施設・記事を「コンテンツコレクション」で型安全に管理。必要な箇所だけ動的アイランド化 |
| 地図 | **Leaflet ＋ OpenStreetMap** | 完全無料・APIキー不要。MVPのトラフィックならOSMタイル利用ポリシー内。増加時はOpenFreeMap等の無料タイルへ差し替え可能な抽象化をしておく |
| ホスティング | **Cloudflare Pages（無料枠）** | 要件N-2で決定済み（広告可・帯域無制限） |
| ライブ検知 | **GitHub Actions（cron）＋ YouTube Data API v3** | 後述§5。**公開リポジトリ**にすることでActions実行時間無制限（私有だと月2,000分制限に触れる恐れ） |
| 解析 | **Cloudflare Web Analytics** | 無料・Cookieレス（同意バナー不要）。GA4は必要になってから追加 |
| 問い合わせ | Googleフォーム（リンク方式） | 無料・実装ゼロ |
| フォント | システムフォントスタック | 日本語Webフォントは重くCWVを毀損。装飾フォントは将来必要時にサブセット化して検討 |

**リポジトリ構成**: `web-experiments/capybara-portal/` を独立gitリポジトリとしてGitHubに公開（Cloudflare Pagesのデプロイ元＋Actions実行場所）。APIキーはGitHub Secrets管理、ローカルは`.env`（`.gitignore`済み）。

## 4. 画面仕様（モバイルファースト）

### 4.1 トップ（ライブ・映像ハブ）
上から順に：
1. **ヘッダー**: ロゴ／ナビ（マップ・温泉カレンダー・記事）／ダークモード切替
2. **🔴 ライブ中セクション**（配信検知時のみ出現）: 配信カード（サムネイル→タップでYouTube埋め込みをその場で再生）。施設名・開始時刻・独自解説つき
3. **いつでも見られるカピバラ**（24/7海外配信）: Taronga等の稼働確認済み配信。稼働状況バッジ（`稼働中/停止中・最終確認日`）つき。停止中は自動で下位に沈む
4. **よりぬきアーカイブ**: 露天風呂LIVE・池掃除などの名場面（手動キュレーション、各配信に解説文）
5. **新着カピバラ動画フィード**: 登録チャンネル群の最新投稿をRSS（クォータ消費ゼロ）で自動集約し「今日のカピバラ」として表示。ライブ供給の少なさを補い毎日更新の体験を作る（2026-07-09追加承認）
6. **今シーズンの温泉情報ストリップ**: 開催中の園をバッジ表示 → `/onsen/`へ誘導
7. **新着記事**・フッター（PR表記・ポリシーリンク）

**動画埋め込み方式**: サムネイル表示（facade）→クリック時にiframe生成（lite-youtube方式）。理由: ①初期表示の高速化 ②「ライブ終了後の黒画面」回避 ③規約上プレイヤーのオーバーレイ禁止に抵触しない標準手法
**規約対応**: 全動画カードに独自解説文を必ず併載（YouTube由来コンテンツのみのページを作らない）

### 4.2 全国カピバラマップ（/map/）
- 上部: フィルタチップ（`温泉あり` `ふれあい可` `カフェ` `ライブ配信あり` ＋ 地方セレクタ）
- 中央: Leaflet地図（施設ピン。種別で色分け: 動物園=緑/水族館=青/カフェ=茶）
- 下部: カード式一覧（地図と連動）。閉園・休止施設は既定で非表示、トグルで「閉園情報も見る」（鮮度の証明として意図的に残す）
- 詳細データ未整備の施設は「簡易カード」（名称＋公式リンクのみ）で網羅性を確保

### 4.3 施設詳細（/spots/[slug]/）
1. 施設名・種別・都道府県・**情報最終確認日**
2. カピバラ情報ブロック: 頭数/個体名・ふれあい/餌やり・見どころ
3. **温泉イベントブロック**（該当施設）: 今季期間・時間・変わり湯情報。「開催中」判定バッジ
4. 基本情報表: 料金・開園時間・休園日・アクセス・公式リンク
5. ライブ/動画ブロック（該当施設）: 配信傾向＋最新アーカイブ
6. **収益導線ブロック**: 「🎫 チケットを探す」「🏨 近くの宿を探す」ボタン（アフィリエイトリンク。提携承認前はプレースホルダー非表示）
7. ミニ地図＋近隣のカピバラ施設
- ページ上部に「本ページはプロモーションが含まれています」表記（アフィリエイトリンクがあるページのみ）

### 4.4 温泉カレンダー（/onsen/）
- **横棒タイムライン**（11月〜4月）: 施設ごとの開催期間をバー表示。今日の位置に縦線
- 各バーに「開催中 / まもなく終了(2週間前) / 今季終了 / 発表待ち」バッジ（閲覧時に日付から自動判定）
- 「カピバラの長風呂対決」等の横断イベントを特集枠で表示
- シーズンオフ（5〜10月）は「今季の発表待ち一覧＋昨季実績」を表示し、通年で価値が出る構成

### 4.5 記事（/articles/[slug]/）
- Markdownベース。目次自動生成・関連施設カードの埋め込みコンポーネント・構造化データ（Article）
- 初期ラインナップ（SEOサジェスト実測に基づく・8本）:
  1. カピバラ温泉はいつからいつまで？全国開催期間まとめ【毎年更新】
  2. 関東でカピバラとふれあえる施設まとめ
  3. 関西・東海でカピバラに会える施設まとめ
  4. カピバラカフェ全国ガイド（料金・予約比較）
  5. 元祖・伊豆シャボテン動物公園のカピバラ露天風呂ガイド
  6. カピバラの長風呂対決とは？全国5園同日開催の名物イベント
  7. カピバラライブカメラ・配信まとめ（当サイトの使い方兼用）
  8. カピバラってどんな動物？生態Q&A（なぜ温泉に入る？）

## 5. ライブ検知アーキテクチャ

```
GitHub Actions (cron: 30分間隔)
  └─ scripts/check-live.mjs
      1. channels.json の各チャンネルの RSSフィード取得
         https://www.youtube.com/feeds/videos.xml?channel_id=... （APIクォータ消費ゼロ）
      2. 直近動画IDを集約 → videos.list を1回バッチ呼出（最大50件/1ユニット）
         → liveBroadcastContent = live / upcoming / none を判定
      3. 補完: 1日2回だけ search.list(eventType=live) を全チャンネルに実行
         （RSS掲載漏れ対策。search.list独立枠100回/日の範囲内）
      4. data/live-status.json を生成 → **`data`ブランチ**へコミット
```

- **クォータ試算**: videos.list 48回/日=48ユニット（枠10,000）＋search.list 10回/日（枠100）→ 余裕
- **`data`ブランチに書く理由**: mainに書くとCloudflare Pagesのビルドが都度走り**月500回の無料ビルド枠を超過**するため。Pagesは`main`のみデプロイ（プレビュー デプロイ無効化）
- **フロント側**: クライアントが `raw.githubusercontent.com/<owner>/<repo>/data/live-status.json` をfetch（CORS許可済み・キャッシュバスター付き）→ ライブ中セクションを描画。fetch失敗時はセクション非表示（サイトは静的部分だけで完全動作）
- **Actions停止対策**: 60日無コミットでcronが止まる仕様への対策として、live-status.json更新自体がコミットになるため実質不要だが、変更なし時もタイムスタンプ更新で担保
- **掲載前チェックリスト**: 各チャンネルの埋め込み許可を実機確認 → `channels.json`の`embedOk`フラグに記録。falseは「YouTubeで見る」リンク方式

## 7. デザイン方針

- **テーマ**: 温泉×カピバラの「ゆるい・あたたかい」。ベース=生成りホワイト、アクセント=カピバラブラウン（#A5714E系）＋湯けむりオレンジ。ダークモード=焦げ茶ベース（prefers-color-scheme準拠＋手動トグル）
- 角丸大きめ・余白広め。イラスト調のロゴ/ファビコン（SVG自作。AI生成画像は使わない）
- アクセシビリティ: コントラスト比AA準拠、地図フィルタはキーボード操作可

## 8. SEO・計測仕様

- タイトルパターン: 施設=`{施設名}のカピバラ情報｜料金・温泉・ふれあい【{サイト名}】`／温泉=`カピバラ温泉カレンダー{年度}｜全国の開催期間まとめ`
- 構造化データ: 施設=`TouristAttraction`（+営業情報）、記事=`Article`、温泉まとめ=`FAQPage`（Q:いつから？A:…）
- `sitemap.xml`・`robots.txt`・OGP（既定ブランド画像1枚、記事は任意で個別）・canonical はサイトURL設定（`SITE_URL` 1変数）から生成 → **将来のドメイン移行は設定1行＋リダイレクトで完結**（要件Q1対応）
- パフォーマンス目標: Lighthouse Performance/SEO 90+（モバイル）
