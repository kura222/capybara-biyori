## P0: 基盤構築

**作業**
1. `web-experiments/capybara-portal/site/` にAstroプロジェクト作成（TypeScript・静的出力）
2. 独立gitリポジトリとして初期化（`.gitignore`に`.env`等。GitHub公開はP5まで保留）
3. デザイントークン定義（カラー・角丸・タイポグラフィ、ライト/ダーク両テーマ）
4. 共通レイアウト（ヘッダー・ナビ・フッター・PR表記コンポーネント・ダークモード切替）
5. `SITE_URL`等の設定一元化（将来のドメイン移行対応）

**検証**: ローカルプレビューでモバイル/デスクトップ×ライト/ダークの表示確認

## P1: 施設DB＋マップ＋施設詳細

**作業**
1. スキーマ実装（コンテンツコレクション＋zodバリデーション）
2. **施設データ収集**: リサーチ済み14件を投入 → 残り16〜26件をリサーチエージェント並列（4〜6体・孫生成なし）で公式サイト裏取り収集 → 私がスキーマ整形・検収（`lastVerified`必須）
3. 簡易リスト施設（詳細なし・名称＋公式リンク）を50件程度まで拡充
4. /map/ 実装（Leafletアイランド・フィルタチップ・カード一覧連動・閉園トグル）
5. /spots/[slug]/ 実装（温泉ブロック・収益導線ボタンは提携前のため楽天トラベルのみ有効）

**検証**: 全件スキーマバリデーション通過／公式URL生存確認（リンクチェッカー）／地図ピン座標の目視抜き取り確認

## P2: 温泉カレンダー

**作業**: /onsen/ タイムライン実装（期間バー・今日線・開催中/まもなく終了/発表待ちバッジの日付自動判定）、長風呂対決特集枠、オフシーズン表示（昨季実績）
**検証**: 日付をモックして4状態（開催中/直前/終了間際/オフ）の表示切替をテスト

## P3: ライブ・映像ハブ

**作業**
0. **ライブカメラ第2次深掘り調査**（エージェント並列）: (a)施設リスト約90件の公式YouTubeチャンネル総当たり（ライブ実績チェック） (b)多言語掃討（西: carpincho en vivo／葡: capivara ao vivo／韓・中）＋Twitch等YouTube外 → `channels.json`拡充
1. `channels.json` 整備（国内4＋海外2〜3＋第2次調査の追加分）
2. **埋め込み可否の実機確認**（各チャンネルの動画をローカルで実際にembed）→ `embedOk`記録。不可はリンク方式
3. lite-youtube方式の動画カードコンポーネント（解説文必須スロット＝規約対応）
4. `scripts/check-live.mjs`（RSS→videos.list→live-status.json生成）＋GitHub Actionsワークフロー（cron 30分・dataブランチへコミット）
5. トップページ完成（ライブ中/24-7/アーカイブ/温泉ストリップ/新着記事）
6. フロントのlive-status fetch＆描画（fetch失敗時は非表示のフォールバック）

**検証**: APIキーでcheck-liveをローカル実行し実チャンネルで検知テスト／ライブ0件時・fetch失敗時の表示確認
**ユーザー作業**: Google CloudプロジェクトでYouTube Data APIキー発行（無料・手順は私がガイド）

## P4: 記事＋基盤ページ

**作業**: 仕様§4.5の記事8本執筆（リサーチ済み一次情報ベース・各1,500字目安）、/about/・/privacy/（解析・アフィリエイト・ステマ規制表記）、OGP画像・構造化データ・sitemap・robots
**検証**: Lighthouse（モバイル）Performance/SEO 90+／構造化データテスト／全内部リンク確認

**作業（私）**: GitHub公開リポジトリ作成＆push、Actions Secrets設定ガイド、Cloudflare Pages接続手順ガイド（`capybara-biyori.pages.dev`空き確認含む）、公開後の動作検証（本番でのライブ検知・全ページ）

## 運用設計（公開後）

- **自動**: ライブ検知（30分毎）・リンク切れ月次チェック（Actions）・**ニュース自動監視**（Googleニュース RSS「カピバラ 閉園/オープン/温泉」等を日次チェックし変化の兆候を通知。反映は検証つき手動）〔2026-07-10 ユーザー質問を受け追加〕
- **季節運用**: 9〜11月に各園の温泉期間発表を確認して更新（年1回の集中作業）・1月の長風呂対決特集
- **成長後**: 独自ドメイン追加→AdSense申請／施設データ全国網羅拡張／診断コンテンツ追加（要件v1.1参照）

## リスクと計画上の対応

| リスク | 対応 |
|---|---|
| 施設データ収集の工数膨張 | MVPは詳細30〜40件で切り、残りは簡易カード。エージェント並列で収集し私が検収 |
| 埋め込み不可チャンネルが多い | P3冒頭で実機確認を先行し、リンク方式へ早期切替判断 |
| ASP提携の承認待ち | サイト公開を先行し、承認後にボタン有効化（実装は条件分岐済み） |
